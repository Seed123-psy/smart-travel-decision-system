# 多 Agent 行程生成

## 本地运行

在已有 MySQL 迁移、DeepSeek 与高德 Web 服务配置之上启动前后端。页面先检查需求，再明确确认联网规划与本地保存；提交后获取任务 ID，每秒读取实际执行状态。关闭或刷新页面不会再次调用模型；可恢复上次任务，也可打开本机历史。

同一后端进程只执行一个任务，第二个提交返回 `409 TASK_BUSY`。请使用单个 Uvicorn worker；此阶段未实现跨进程调度或身份认证，服务仅绑定 `127.0.0.1`。一次生成会调用 DeepSeek 和高德，页面刷新和状态查询本身不调用供应商。

## 角色与职责

- 景点 Agent：根据城市与偏好选择查询参数，检索高德风景名胜类（`110000`），并核验真实 `typecode`，排除城市、车站等非景点。
- 住宿 Agent：根据住宿需求选择查询参数，检索住宿服务类（`100000`）；无需住宿时跳过，有候选时 Planner 必须选择真实酒店。
- 天气 Agent：查询目的地行政区和实际预报，保留预报日期。
- 营业状态 Agent：在景点候选产生后选择要核实的地点，调用高德详情；缺少营业证据时标记未知。
- Planner：读取上述角色的共享结果，以真实 POI ID 组织每日活动，输出结构化草案。

角色使用 HelloAgents 基类和独立提示词，通过可取消的 DeepSeek 异步适配调用模型。工具由白名单及参数校验限制；角色之间传递归一化数据与来源，不保存模型思维链。路线校验和预算状态由确定性服务处理，不计作 Agent。

## 接口与状态

| 接口 | 用途 |
| --- | --- |
| `POST /api/trips/plan` | 接收已确认的 `TravelRequest`，保存需求和任务，202 返回 `task_id`、`trip_id` |
| `GET /api/tasks/{task_id}` | 当前阶段、真实 Agent 状态、耗时、工具摘要及结果地址 |
| `GET /api/trips/{trip_id}` | 原始确认需求、当前版本行程、校验和预算状态 |
| `GET /api/trips?limit=20&offset=0` | 本机历史；单页最多 50 条 |

任务终态是 `ready`、`degraded` 或 `failed`；存在可展示但未验证的信息时为 `degraded`。总期限 60 秒包含收集、Planner、规则校验与保存，不自动重复付费规划。期限到达后取消未完成调用并记录失败。服务启动会把遗留运行任务标记为 `SERVER_RESTARTED`，用户可重新提交；不承诺断点续跑。

保存结果时，`trip_versions`、`trips.current_version` 与任务终态在同一事务提交。提交失败不发布可用结果；数据库短暂中断时返回安全错误，恢复后补写终态。刷新读取历史不会重新校验已经过去的旅行日期。

HTTP 提交断开后，受追踪的创建流程仍负责启动已保存任务；过期但未结束的记录在下一次读取时补记失败，避免永久停留在等待状态。

## 当前结果边界

活动 ID 必须来自真实检索、位于同一大陆城市；日期须完整覆盖请求，活动须在每日窗口内且不能重叠。相邻活动按高德步行耗时加 10 分钟缓冲检查衔接，缺失路段标未知，超时标冲突。当前不提供驾车、公交、酒店接驳或往返城际交通规划。

营业详情不代表旅行当天开放或预约成功；天气只用于供应商返回的同城日期。所有时长仍是建议与估算。价格缺少可信来源时为 `null`；预算显示“尚未完成费用精算”，不会用零元或完整预算通过代替未知。

来源记录保留生成时的提供方、查询时间和有效期。`source_url` 是不含密钥的接口标识，不能直接作为浏览器链接；页面将已知高德接口映射到公开的服务说明，并准确标为“说明”，不把说明文档当作某次查询的原始响应。历史行程沿用此映射，无需重新生成或修改已存快照。

互动地图、PDF、自然语言需求解析、行程删除、单项编辑、Critic 与费用精算尚未实现，完整 P0 尚未验收。

## 验证

在 `backend/` 运行 `python -m pytest`；`MYSQL_INTEGRATION_URL` 显式配置后启用 MySQL 测试，事务回滚全部测试写入。角色测试使用可控模型与工具响应，不消耗外部配额。真实生成通过页面显式提交验证，脱敏报告记录任务、模型、耗时和数据覆盖，单次通过不等同于 20 次 p95 性能验收。
